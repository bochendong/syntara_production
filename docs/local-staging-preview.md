# 本地 UI 与测试服对照

日常调整测试服 UI 时，从当前任务工作树运行：

```bash
pnpm staging:preview
```

固定入口：<http://127.0.0.1:1422/test/app?as=teacher>。运行的入口是测试服同一个
`apps/native/src/App.tsx`，使用 `VITE_SYNTARA_WEB_APP=1` 和 staging channel；
不安装演示课程，不替换课堂响应。前端改动可以通过 Vite 热更新查看。

启动前读取线上 `/api/native/v1/version`，确认当前工作树包含正在部署的提交。
基线缺失或测试服不可访问时拒绝启动，不自动切回旧源码或模拟数据。
如果工作树落后，先按 `docs/branch-state.md` 整合当前测试服基线，并保留本地改动。

右下角预览面板显示本地／线上提交、分支及 UI 源码是否一致。检测范围是原生 App 的
`src`、`public` 和 `index.html`，包括未提交及未跟踪文件；这不是完整构建哈希证明。
每 30 秒及返回标签页时重新核对。部署变化或核对失败会明确提示。
真实数据入口和 QA 演示使用各自页面，但**共享 localhost 的浏览器缓存**，不要把 QA
数据导入完整 App。与远端测试服的 IndexedDB、界面偏好和登录意图各自独立。

## 数据与写操作

本地网关读取已有设备账号的测试服数据。默认凭据文件是
`~/.config/syntara/staging-backend.json`，也可显式传入：

```bash
pnpm staging:preview --credential-file /absolute/path/to/device.json
```

只支持本机同源请求和列出的 GET 路由，沿用服务端账号权限。设备凭据仅在 Node 进程使用，
不返回浏览器、不写进前端环境变量或存储；不复制 Google 会话 cookie。
所有保存、开课、提交、AI 和后台上传请求被本地网关阻止。「打开班级」导航会通过只读
GET 查询已有班级；尚未开班时拒绝创建，不向上游发送 POST。
因此课程和课堂可用真实数据核对 UI，但日历／偏好等 POST 同步不会完成，不能用此模式
验收写入流程；需要验证保存结果时使用真正的测试服。已有账号状态和本机偏好不同也会
影响所见内容。当前预览设备账号不一定是远端浏览器已登录的账号，请核对「我的」。

## 演示入口

`/qa/teach.html?screen=classroom` 与 `?screen=live` 是隔离的课堂状态夹具，
只用于查看空状态、备课和上课中的布局。所有 Vite 开发页面都会显示环境标识，
`/qa/` 明确显示「演示页面 · 模拟数据」。不要以演示数据判断测试服课程或功能状态。
模拟课堂操作只影响该页内存。

同一固定端口已被占用时启动失败，不另开随机端口，不接管其他任务的服务。
旧工作树的 3000／1420 页面不能作为当前测试服的默认 UI 参照。
