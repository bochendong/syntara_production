# Web 端角色与学期课程架构

## 产品入口

- 学生入口：`/login` → `/learn`
- 教师入口：`/teacher/login` → `/teacher`
- 两端共用 iPadOS 风格桌面，但应用集合由角色决定。点击任何 App 图标后进入完整 App 页面或全屏 App surface，不把 App 本身装进弹窗；只有 App 内的短任务（例如选择迁移内容）使用弹窗。
- 学生课程图标进入原 `/learn?courseId=...` 学习工作区；教师课程图标进入课程内容工作台。

学生端只显示教育机构同步且已开启 AI 资格的 `CourseAccess` 课程。学习工作区保留聊天、学习进度、课程资料阅读和练习入口，不渲染任何文件选择器或上传按钮。教师端不显示学习日程与 Haru 小组件，整页是课程和教师工具组成的统一应用网格。系统 App 与课程 App 使用相同图标尺寸，并默认排在课程前面。

## 教育机构 API 边界

教育机构 API 是课程与访问关系的唯一事实来源。老师登录成功后，平台按当前老师请求其当学期课程列表；这份结果只需要对该老师完整，不需要先聚合全机构快照：

- `courses` 告诉系统当前登录老师正在教授哪些课程实例；机构是任课关系的唯一决定方，平台教师端和管理员端都不提供创建课程或手动换老师入口。
- `studentEnrollments` 告诉系统学生属于哪门课以及 `aiEnabled` 是否开启；教师端不提供创建学生、授权或撤销入口。
- 机构在学期中把 A 老师改派为 B 老师时，B 登录响应中的稳定课程 ID 会命中同一个课程实例，平台结束 A 的任课关系并创建 B 的任课关系。课程内容不复制、不转移；B 第一次进入课程时就能看到 A 上传、迁移和生成的全部当前有效内容，并接管内容管理权。
- 响应中缺失的课程只撤销当前登录老师自己的旧任课授权，不删除课程或内容，也不撤销其他老师和学生的授权。
- 本地开发仍使用 IndexedDB 模拟同一契约；未来接入真实 API 时，页面与数据读取函数不需要改写。

当前本地教师登录会调用 `POST /api/local-school/teacher-current-courses`。该路由是教育机构适配器的演示实现，返回老师维度的 `teacher_current_courses` 响应；生产环境在此边界接入学校已认证的课程接口。

老师和学生每次本地账号登录成功后，都会自动逐门同步加拿大默认学期规则下的本学期课程内容。教师先刷新机构任课列表，再同步所有当学期任课课程；学生只同步机构已经授予且 `aiEnabled` 未关闭的当学期课程。登录同步刷新课程资料索引和完整笔记正文，PDF 等大源文件仍在用户打开时按需下载。单门课程的服务端内容暂不可用时保留浏览器现有副本并继续登录，避免可选 PostgreSQL 不可用时破坏 local-first 模式。

教师任课交接、上传、迁移、假删除和内容版本的完整业务契约见 [`teacher-course-content-lifecycle.md`](./teacher-course-content-lifecycle.md)。

## 本地数据模型

本地测试数据保存在浏览器 IndexedDB（Dexie）中：

- `localSchoolAccounts`：学校分配的本地账号与角色。
- `academicCourses`：一条记录代表一个课程学期，并保存机构稳定课程 ID 与当前任课老师快速读取字段。
- `courseAccess`：账号到课程学期的当前授权；学生授权继续包含 `aiEnabled` 状态。
- `instructorAssignments`：机构决定的教师任课时间段，保留学期内 A → B 的交接历史。
- `courseContentAssets`：全局内容资产，保存笔记本、题库或源文件的唯一记录。
- `courseContentAssetVersions`：不可变内容版本；迁移固定指向选中时的版本。
- `courseContentReferences`：带版本、状态、来源和操作者的课程内容项；同一资料可重复出现。
- `courseContentEvents`：任课交接、上传、迁移、生成、隐藏和恢复的追加式审计事件。
- `localSourceFiles`：源文件 Blob 与文件元数据。
- `localCourseKnowledge`：已经提取并写入课程 AI 知识的正文。
- `localKnowledgeQueue`：源文件 AI 入库任务及进度。
- `localAiUsageEvents`：教师与学生共用的逐次 AI 调用审计明细，记录账号、角色、课程与活动类型。
- `localAiUsageDailyRollups`：按账号、UTC 日期、模型、课程和活动增量维护的每日 Token 桶。
- `localAiUsageTotals`：每个账号一行的累计调用数与 Token 总量。

同一课程代码可以有多个年份和 Term。加拿大默认学期规则为：1–4 月 Winter、5–8 月 Summer、9–12 月 Fall。

## 往届课程与选择性迁移

教师主屏幕只读取教育机构 API 在加拿大规则下分配给该教师的当学期课程。往届课程不归某位教师个人所有，而是机构内按课程编号积累的共享历史：教师本学期被分配 `CSC108` 后，可以浏览同一机构中所有更早 Term 的 `CSC108`，包括其他教师建设的课程版本，但不会看到本学期未教授的其他课程编号。

这些内容位于独立的 `/teacher/past-courses` App 页面。页面先读取仅含 `academicYear`、`term` 和课程数的轻量目录；教师选择一个 Term 后，右侧才分页读取该学期符合课程编号范围的课程卡片。点击“迁移内容”后，才在 App 内弹窗中选择同课程编号的当学期目标课程，再按笔记本、题库、源文件逐项勾选。教师与学生用量统计分别使用独立的 `/teacher/usage` 和 `/student/usage` App 页面。

迁移只新增目标课程的内容项，不复制底层文件，也不修改来源学期。正式模型会让目标内容项锁定明确的资产版本；老师再次主动迁移相同内容是合法操作，系统不按文件内容提示或阻止。

老师上传相同文件时，系统不做业务重复判断、不提示、不阻止。每次上传形成独立的课程内容项；底层可以按内容哈希静默复用二进制 Blob，但这种物理优化不会改变老师看到的课程内容。

老师从当前课程移除内容时只隐藏目标课程的内容项。教师默认列表、学生视图和当前课程 AI 检索不再使用该项，但底层资产、来源学期原版和审计记录不被物理删除。

## 上传与 AI 知识队列

教师课程工作台把两个动作明确分开：

1. “上传源文件”只保存文件与课程引用，不自动消耗 AI 处理资源。
2. 教师点击源文件旁的“加入 AI 知识库”后，才创建队列任务。

本地 worker 每次只处理一个任务，阶段依次为：

`queued → extracting → writing_knowledge → creating_notebook_reference → completed`

失败任务保留错误和尝试次数，可以重试。完成后会写入课程知识记录，并建立一个派生 AI 笔记本引用。正式部署时可以把 worker 换成服务端队列；前端任务阶段和数据契约不需要改变。

## 页面加载策略

- 学生首页只读取当前账号的授权课程，不先读取课程正文。
- 登录完成前会对本学期授权课程执行一次内容增量同步；首页本身仍只读取已经同步到 IndexedDB 的轻量课程索引。
- 教师首页只读取当学期课程的轻量索引；“往届课程”应用首次只读取 Term 目录与各 Term 的课程数，不返回课程名称。
- 选择 Term 后，右侧每页只读取该 Term 中与教师当学期课程编号匹配的 12 门课程；切换 Term 时替换这一页数据。
- 往届课程卡片不读取内容详情；只有打开迁移弹窗时才加载所选课程的内容索引。
- 教师课程工作台先读取轻量计数；源文件每页 8 项。
- 教师课程工作台包含只读“学生名单”页签，只列出当前 active 且 `aiEnabled` 未关闭的学生，并展示机构同步的姓名、手机号与头像；教师不能在这里增删授权。
- 教师课程工作台的“课程资源”页签只展示笔记本和题库；源文件只在独立“源文件”页签出现，不在两个分组重复展示。
- “课程资源”沿用学生课程右侧栏的资料库入口：题库打开列表，笔记本库使用同款笔记本封面卡片网格并进入详情预览；两类课程引用都可从列表或详情删除，并在“已移除”中恢复。
- 旧笔记本引用缺少结构化章节时，详情页按 `sourceFileId` 回读关联源文件正文，不把压缩后的简介误当成完整笔记内容。
- 课程资源库列表不预取所有源文件正文；教师点击“在线预览”后才按需读取单个 Blob。PDF 以内嵌原页预览，Markdown 和纯文本直接阅读，PPTX/DOCX 提取可见文本预览。
- AI 队列使用单 worker 和轻量轮询，避免多个文件并发解析拖慢页面。
- 用量统计的总览卡片读取单行 `localAiUsageTotals`，趋势图只读取最近 7 天的 `localAiUsageDailyRollups`，明细通过 `[userId+createdAt]` 索引倒序限制为 10 条；页面不会拉取全部 `localAiUsageEvents` 再求和。

用量事件、每日桶和账号总计在同一个 IndexedDB 事务中写入；事件 ID 已存在时不会重复累加。数据库升级到 v17 时会一次性把旧教师账本迁移到通用聚合表，之后所有新增用量都走增量更新。正式服务端数据库应保持相同边界，并用事务或幂等消费保证事件账本和聚合值一致。

## 正式上线边界

当前用户名密码、机构 roster 快照和队列都用于单浏览器本地测试。上线前应由服务端定期拉取或接收教育机构 API 快照，把相同数据契约迁入服务端数据库，并用服务端 session、角色和机构课程授权再次校验每个读取、上传与队列 API；不能只依赖前端隐藏按钮。
