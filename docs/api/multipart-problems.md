# 分小问题型

`multipart` 将原卷的同一大题保存为一个题目 ID。共享题干放在 `publicContent.stem`，每个小问有稳定 `label`、权重 `points`、可选前置小问 `dependsOn` 和独立 `content`；`grading.parts` 按 label 保存对应参考答案与评分数据。支持选择、简答、证明、计算与填空小问。

宽屏在共享题干旁依次显示所有小问卡片；980px 以下一次显示一问，可通过珠子、上一问/下一问或横向触摸滑动切换。中英文递归应用到每个小问，编号、权重和评分数据保持一致。每问可单独提交，或一起提交已修改的小问；没有本次提交的小问沿用之前的作答与结果。自动判分的小问分别计算提交次数和分数上限。批改失败不扣除该问提交次数，并保留输入供重试。

重置与参考答案确认沿用现有做题页：重置清空当前各问输入，历史成绩与各问评分记录保留；查看答案前保存完整的小问作答快照与 AI 求助记忆，未评分事件不覆盖之前的逐问结果。参考答案按小问排列。只有一个小问提交成功时不会提前提示整组完成。

## 导入与旧题修复

新卷子的同一大题号优先整理成一道 multipart 题。相邻小问可按同一原题号/共享题干合并；明确不同大题号或不同来源的题不合并。挤在一段里的小问会分成共享题干和子题。自动整理不会把未获得的参考答案冒充为已补齐答案，后续补答案流程仍检查每问。

教师网页题库的「小问体检」先列出合并/拆分建议；老师选择后才修复，也可忽略。旧题不会在扫描或发布迁移时自动改写。合并时旧题归档并保留原作答记录；单题拆分保持原 ID。测试版 MAT102 的本次批量结构整理使用独立的管理员预览/应用接口，直接保留原题 ID，不删除或归档题目。

管理员 `POST /api/admin/courses/[id]/problems/multipart` 默认预览；显式 `apply:true` 才写入。每条变更要求当前 `expectedRevision`，整批检查后在事务中原地更新；重放同一内容返回 unchanged。只接受本课程未归档公有开放题的 multipart 结构、完整参考答案和匹配评分 label，拒绝重复编号、不完整答案、错误前置依赖及并发修改。路由要求已有管理员会话和严格同源 Origin；不接受任意用户 ID，不创建权限或模拟学生身份。写入只涉及题目结构、去重索引、内容更新时间和课程内容版本，不修改题号、章节、来源、笔记及学生历史。

## 将过长的独立题组拆成多道

单道 multipart 仍最多 12 问。互相独立的练习可按内容拆成两或三道较短题组；例如 20 问极限拆为两道各 10 问，15 问相关变化率拆为三道各 5 问。需要前问结果的推导不跨组拆开。题组内保留原小问标签，方便对照原卷；每组的评分权重单独归一化。

管理员 `POST /api/admin/courses/[id]/problems/multipart/split` 默认预览，使用与原地修复相同的管理员会话、同源和版本保护。每条变更包含原题 `id`、`expectedRevision`、按原顺序列出的完整 `sourceLabels`，以及 2–3 个 `groups`。每组提供 `title`、可选 `localizedTitles`（`en-US`/`zh-CN`）、完整 `publicContent` 与 `grading`。双语列表标题同时放在公开内容的 translations 中。每个小问必须恰好出现在一组、顺序不变，且具有答案、评分和合法的组内前置依赖；一组不能超过现有 12 问限制。

显式 `apply:true` 在可串行化事务中创建新组、增加课程内容版本，并归档原题。原题的 ID、完整题面、答案、题号和学生历史均保留；不删除、重写或迁移学生的 attempt/progress。新题沿用课程、章节、笔记、来源、难度和标签，分配新的课程题号；原题的 sourceMeta 保存对应替代组的审阅哈希和 ID。新组 ID 稳定且保留组序，同一计划重放只返回 unchanged；原题版本过期、替代组被编辑、覆盖不完整或去重冲突均拒绝写入。客户端完整题库同步会归档已撤下的旧题并加入新组。

`node --test scripts/maintenance/verify-multipart-split.test.mjs` 覆盖预览不写入、20→2×10、原题保留、连续新题号、重放不写入，以及过期版本、其他课程、不完整/重复小问、超限题组和已编辑替代组的拒绝。
