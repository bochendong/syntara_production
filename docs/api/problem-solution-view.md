# 题目重置与参考答案

原生/测试版做题页的选择、证明、简答、计算、填空、编程六种题型共用「重置」与「查看答案」。重置清空本次输入，编程题恢复起始代码；历史评分与提交次数保留。填空题显示完整的 `stemTemplate` 并提供文字输入。

参考答案来自题目的既有评分资料：正确选项、参考证明/答案、可接受填空值、参考代码及解析。没有参考资料时明确提示未配置，不根据学生输入生成答案。2026-10-26 对测试版四门课程的 551 道题进行只读检查，均有可显示的参考资料。

## 确认与保存

首次点击打开模态确认框，说明保存当前作答与进度、记录求助信息供 AI 了解卡点。取消不显示答案、不写入记录。勾选「记住这次选择，下次不再提醒」仅在保存成功后记住；偏好按当前账户隔离，保存在本机。保存失败时保留弹窗与作答，提示重试。记住偏好后仍会保存每次新作答的快照。

查看前先通过本地仓库保存快照与求助记忆，均保存成功后才显示答案（浏览器仓库使用同一 IndexedDB 事务）。快照使用 `solution_viewed` / `answer_reset` 学习事件。事件携带完整作答，以及查看/重置时的 `status`、`score`、`attemptedCount` 进度副本。它们不更新已评分的进度；历史中明确标为未评分。查看答案同时写入课程级 `solution_help` 记忆，包含题目、章节、当时的输入与进度；重置不创建求助记忆。同一题重新作答后的求助会更新该题记忆，完整事件快照仍保留在历史中。

## 同步与 AI

原有题目上传协议增加可选的 `event` 和 `progressSnapshot`。服务端强制这些事件为 `pending`、空分数，并用 `preserveProgress` 写入历史而不增加提交次数、改写成绩或触发批改学习作业。按原有客户端记录 ID 去重与课程/题目权限检查；普通提交保持原有流程。旧进度回退统计排除这两类事件。

求助记忆沿用课程学习记忆同步。下一次构建聊天上下文时重新读取仓库记忆，避免已挂载页面的旧 workspace 隐藏刚保存的求助记录。查看答案本身不调用模型、不自动判断学生答错。离线时先保存本地，沿用现有同步队列重试。

## 验证

`node --test scripts/maintenance/verify-problem-solution.test.mjs` 检查六种答案来源、重置初值、快照与 AI 记忆、保存失败、账户偏好、服务端进度保留、上传去重/权限和下一次聊天上下文。隔离浏览器样例验证取消、确认、记住选择、刷新后偏好、六种题型重置及代码草稿恢复。测试不会修改真实学生记录。
